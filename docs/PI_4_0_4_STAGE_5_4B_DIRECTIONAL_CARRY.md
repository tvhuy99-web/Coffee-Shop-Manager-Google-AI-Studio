PI now compares eight bounded directional carry intentions using predicted endpoint, corridor risk, pressure, territory, energy and the existing state-value scale. One chosen direction competes with other action families (no extra RNG per direction). Hold can choose a protection step away from a nearby opponent; stationary hold is still possible. The engine executes the same direction and duration from the actual release position. A local earliest-reachable defender search schedules a contact before the endpoint; selected carrier and challenger use the predicted path, and the central integrator charges movement once. No automatic tackle at 6.5m for the timed carry; a planned challenger must physically reach. Shielding uses strength/balance/composure/technique instead of sprint/dribble ability, with an approximate protective body orientation. Legacy positive-dt duel API remains. Checkpoint retains intention, challenger path, mode and time; policy ID changes.

Diagnostics: actual elapsed hold/carry milliseconds, starts, shield/lateral intentions, contacts and turnovers. No changes to pass/shot execution or goal probability; no target-statistics feedback. Tests cover directional geometry, reachable early contact, snapshot/replay and prior timing/physics. Approximation: a single predicted challenger and fixed target path per interval, sampled at 50ms; no multi-defender collision, foot-specific ball offsets, continuous interception during all decision-preparation intervals, or full pressing assignment yet. Do not equate directional selection with complete ball shielding physics. Previous Passing, First Touch, QA10, pressing and Android regressions remain separate. Review same cohort before 5.5.
